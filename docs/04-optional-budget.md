# Optional：監視リソースグループの予算アラート

[README](../README.md) | [Step1：Azure VM のログ収集](02-azure.md) | [Step2：オンプレミス VM のログ収集](03-onpremises.md)

LAW、DCR、アラート規則などを配置した監視用リソースグループ（RG）に、Azure Cost Management の予算とメール通知を設定します。監視の運用では、障害の検知に加えて、ログ量の増加などによるコストの変化も確認します。

この章は任意の演習です。監視用 RG を作成した後であれば、Step1 / Step2 の完了を待たずに実施できます。Azure Portal を使用し、既存のログ収集やアラート規則は変更しません。

## 始める前に

- 対象 RG でコストを閲覧し、予算を作成・変更できるアカウントを使用してください。ロールの例は「コスト管理共同作成者（Cost Management Contributor）」です。閲覧者の権限だけでは予算を作成できません。契約によっては、課金管理者によるコスト閲覧の許可も必要です。新しいサブスクリプションでは Cost Management が利用可能になるまで最大48時間かかる場合があります。[^1]
- 既存の予算、通知先、監視リソースの配置を確認し、演習で追加する予算の名前、金額、利用期間、通知先を管理者と決めてください。
- メール受信を試す場合は、受信できるご自身のメールアドレスを用意してください。この演習では予算にメールアドレスを直接指定するため、Step1 のアクショングループは必須ではありません。[^1]
- **予算は通知の仕組みであり、支出の上限を強制するものではありません。** 閾値に達してもリソースは停止せず、課金も継続します。LAW の日次上限とは別の設定です。[^1]

### 入力例

| 対象 | 例 |
|---|---|
| 監視用 RG | `rg-arclab-monitoring`（既に作成した監視用 RG に置き換える） |
| 予算名 | `budget-arclab-monitoring-monthly` |
| リセット期間 | 月次（Monthly、暦月） |
| 予算額 | `1000`（Portal に表示される通貨で入力） |
| 開始日 | 実施月の1日 |
| 有効期限 | 演習・運用で必要な期間の終了日 |
| メールアドレス | `handson-alert@example.com`（架空の例） |

金額は設定方法を確認するための例であり、監視費用の見積もりではありません。Portal の通貨を確認し、実際の利用量と運用方針に合わせて変更してください。

Step0 / Step1 の既定値では、監視リソースも VM などと同じ `rg-arclab-lab` に配置します。その構成で本章を実施すると、予算の対象は**監視費用だけでなく、その RG の全費用**になります。監視専用 RG がある環境では、その RG を選択してください。本章のために既存リソースを移動する必要はありません。

## 4-1. 対象 RG とコストの範囲を確認する

1. Azure Portal の検索で「リソース グループ」を開き、監視リソースを配置した RG を選択します。
2. 「概要」でサブスクリプションと RG 名を確認し、リソース一覧に今回の LAW、DCR、アラート規則などがあることを確認します。
3. RG の「コスト管理 → コスト分析」を開きます。画面によっては「Cost Management」から「コスト分析」を選択します。
4. スコープが対象 RG になっていることを確認し、期間を「今月」に設定します。サービス名またはリソースでグループ化し、現在の費用と主な課金対象を確認します。

RG スコープの予算は、その RG に計上される費用を対象とします。別 RG に配置した VM、Firewall、Bastion などの費用まで含む、環境全体の予算ではありません。必要なら、それらの RG やサブスクリプションにも別途予算を設定します。[^1]

確認してみよう。選択した RG は監視専用ですか。それとも VM なども含みますか。今回の予算で検知できる費用の範囲を説明できますか。

## 4-2. 月次予算を作成する

1. 対象 RG の「コスト管理 → 予算」を開き、「追加」を選択します。[^1]
2. 作成画面のスコープが、手順4-1で確認したサブスクリプションと RG であることを確認します。サブスクリプション全体のスコープになっている場合は、対象 RG に戻って操作してください。
3. 次の値を入力します。

   | 項目 | 設定 |
   |---|---|
   | 名前 | `budget-arclab-monitoring-monthly` |
   | フィルター | 追加しない（対象 RG 全体を評価） |
   | リセット期間 | 月次（Monthly） |
   | 開始日 | 実施月の1日 |
   | 有効期限 | 合意した終了日 |
   | 予算額 | 合意した月額。例は `1000` |

4. 表示される通貨と費用のグラフを確認し、「次へ」で通知条件の設定に進みます。

月次予算は期間が変わると同じ金額でリセットされます。有効期限を過ぎると予算は自動的に削除されます。作成前の利用分を含め、対象期間の費用を評価するため、作成時点ですでに閾値に達している場合もあります。[^1]

## 4-3. 実績と予測のメール通知を設定する

1. アラート条件に次の3行を設定します。「種類（Type）」で実績と予測を選択します。[^1]

   | 種類 | 予算に対する割合 | 用途 |
   |---|---|---|
   | 実績（Actual） | `80%` | 月内の実績費用が予算に近づいたことを通知 |
   | 実績（Actual） | `100%` | 月内の実績費用が予算額に達したことを通知 |
   | 予測（Forecasted） | `100%` | 月内の予測費用が予算額を超える見込みを通知 |

2. 通知先に、合意した受信可能なメールアドレスを入力します。`handson-alert@example.com` のままでは受信できません。
3. この演習では、アクショングループは選択せず、予算からのメール通知を使用します。既存の通知・自動化を利用する場合は、その実行内容と変更範囲を管理者と確認してください。
4. スコープ、予算額、期間、3つの閾値、メールアドレスを見直し、「作成」を選択します。
5. 予算一覧から作成した予算を開き、設定が保存されたことを確認します。

例えば予算が `1000` の場合、実績80%は `800`、実績100%は `1000` を基準にします。予測100%は実績が `1000` に達する前でも、月内の予測費用が予算を超えると通知するための条件です。[^1]

確認してみよう。イベントを検知する Step1 のログ検索アラートと、費用を評価する今回の予算アラートでは、対象データと評価のタイミングが異なることを説明できますか。

## 4-4. 設定と通知を確認する

### 演習中に確認すること

- 予算のスコープが、対象の監視用 RG になっている。
- 予算額、通貨、月次の期間、開始日、有効期限が意図した値になっている。
- 実績80%・100%と予測100%、通知先メールアドレスが保存されている。
- コスト分析と予算の画面で、同じ RG・期間を見ている。

**設定の保存確認と、実際の予算通知の受信確認は分けて記録してください。** コストデータは通常8～24時間で利用可能になり、予算は24時間ごとに評価されます。閾値に達した場合のメールは、通常は評価後1時間以内に送信されます。ハンズオン中に通知が届くとは限りません。[^1]

### 後日、閾値に達した場合に確認すること

1. 受信メールで予算名、対象スコープ、実績／予測の種類、閾値を確認します。
2. Portal で同じ予算を開き、費用と設定値を見比べます。
3. メールが見当たらない場合は、宛先の誤り、迷惑メール、組織のメールフィルターを確認します。必要に応じて `azure-noreply@microsoft.com` からのメールを受信できるか管理者に確認してください。[^1]
4. コスト分析にデータがない場合や予測が表示されない場合は、費用の反映と予測の表示を待ちます。画面にエラーがある場合は、その詳細とコスト閲覧権限を確認してください。

通知を発生させるために、ログを大量生成したり、不要なリソースを追加したりしないでください。この演習の完了条件は予算と通知条件の保存確認です。受信未確認の場合は、その旨を記録します。

## 4-5. 演習後の扱い

- 運用で継続する場合は、担当者、予算額、通知先、有効期限を見直します。通知後はコスト分析で増加したリソースやサービスを確認し、ログの収集対象・量・保持期間などの対策を検討してください。既存監視の変更は管理者と合意してから実施します。
- 演習用の予算が不要になった場合は、対象 RG の「予算」で `budget-arclab-monitoring-monthly` を選択し、その予算だけを削除します。既存の予算や監視リソースは削除しないでください。
- 予算の削除はリソースの削除や課金の停止ではありません。ラボ全体の片付けは [Step0](01-lab.md) の手順と環境の運用方針に従ってください。
