# 4.2 ワークブックの作成

[4. オプション](04-optional.md) | [Step1：Azure VM のログ収集](02-azure.md) | [Step2：オンプレミス VM のログ収集](03-onpremises.md)

Azure VM と Azure Arc マシンのログをワークブックに表示します。VM ごとの CPU 使用率を一覧で比較し、時系列と Windows イベントを見比べて、負荷やエラーが増えた時間帯を調べられます。

## 完成版 JSON を貼り付けて使う

1. [完成版ワークブック JSON](04-optional-workbook.json) を開きます。GitHub では `Raw` で JSON 本文を表示できます。`{` から `}` までをコピーします。リソース ID やアラート名の書き換えは不要です。
2. Azure Portal で「モニター → ブック → 新規」を開きます。編集モードで `</>`（詳細エディター）を開き、「形式」が「ブック テンプレート」であることを確認します。
3. コード欄の JSON をコピーした本文で置き換え、「適用」を選びます。Markdown のコードフェンスは含めません。
4. サブスクリプション、ログの送信先の Log Analytics ワークスペース（LAW）、監視対象の順に選択します。マシンの初期値は「未選択」です。Azure VM と Arc マシンを合わせて複数選択できます。監視対象が増えたら、ワークブックを開き直すか候補を更新して選びます。既定の期間は過去24時間です。
5. 「保存」で名前と保存先のリソースグループを指定します。ブックの保存先を指定しても、ログの送信先は変更されません。

## タブの使い方

| タブ | 確認できること |
|---|---|
| 概要 | 選択したマシンごとの Heartbeat、直近5分の CPU・空きメモリ、選択期間の `Event` 件数。マシンを対象とするアラートと LAW 全体を対象とするアラートの集計 |
| 性能 | 平均 CPU 順の VM 一覧と、CPU・空きメモリ・ディスク・ネットワークの時系列グラフ。ネットワークは NIC 別 |
| イベント・アラート | `Event` のチャネル別割合、重大度別件数、チャネル・ソース・イベント ID ごとの上位10件。`SecurityEvent` の上位10件は別集計。アラートの発生履歴 |
| 構成 | Azure VM の電源状態と NIC のプライベート IP、Arc の接続状態と OS バージョン、両方の Heartbeat が報告したゲスト OS とプライベート IP |

概要では、Heartbeat が10分以上前、CPU が80%以上、空きメモリが512 MiB未満のいずれかに該当すると「要確認」と表示します。これらは点検時の目安です。データが届いていない項目は空欄になり、Heartbeat がないだけでは停止と判断できません。

イベントグラフに表示されるチャネルは、選択先の LAW の `Event` に取り込んだ範囲です。`Security` が `SecurityEvent` に届く場合は、チャネル別の円グラフには含めず、監査イベントの別表で確認します。LAW 全体を対象とするアラートには、選択していないマシンの通知も含まれます。

## 利用条件

- 選択するマシンと LAW は同じサブスクリプションに配置します。マシンのログは選択する LAW に送信しておきます。ワークブックを保存しても収集は始まりません。
- 閲覧するアカウントに、対象リソースとアラートの読み取り権限、および選択する LAW のログ検索権限が必要です。保存するアカウントにはワークブックの作成権限も必要です。
- 性能パネルは Windows の `Perf` カウンターを使用します。VM Insights の有効化は不要です。VM Insights の `InsightsMetrics` だけを収集している場合、このサンプルの性能パネルには表示されません。

## 性能カウンターを収集する

該当のカウンターが既に `Perf` に届いていれば追加設定は不要です。追加する場合は、LAW の取り込み量と利用期間を確認し、既存 DCR と同じカウンターを同じ LAW に重複送信しないようにします。

1. Portal の「モニター → データ収集ルール → 作成」を開きます。名前は `dcr-arclab-workbook-perf` などとし、LAW と同じリージョンを選びます。テレメトリはエージェントベース、プラットフォームは Windows を選択します。
2. 「リソース」で、性能データを収集する Azure VM と Arc マシンを追加します。既存の AMA と ID、オンプレミス側の Proxy 設定は引き続き使用します。
3. 「収集と配信」で「パフォーマンス カウンター → カスタム」を選び、必要なカウンターを追加します。ハンズオンでのサンプリング間隔の例は `60` 秒です。

   | 指標 | カウンター |
   |---|---|
   | CPU 使用率 | `\Processor Information(_Total)\% Processor Time` |
   | 利用可能なメモリ | `\Memory\Available Bytes` |
   | ディスク読み書き合計（任意） | `\LogicalDisk(_Total)\Disk Bytes/sec` |
   | NIC 別ネットワーク送受信合計（任意） | `\Network Interface(*)\Bytes Total/sec` |

4. 宛先の種類は「Azure Monitor ログ」（画面によっては「Log Analytics ワークスペース」）を選び、使用する LAW を指定します。作成後、「リソース」で対象マシンを確認します。

演習後に性能収集が不要なら、この演習で追加した性能用 DCR の関連付けだけを外します。ワークブックを閉じたり削除したりしても性能データの収集は止まりません。

## 表示を確認する

1. 保存したブックを開き、Azure VM と Arc マシンを選びます。「性能」で両方の系列を確認し、片方の選択を外すと、そのマシンの系列が消えることを確認します。
2. 「イベント・アラート」で期間を変え、チャネル別・重大度別の件数と上位10件が選択した期間に切り替わることを確認します。必要に応じて LAW の「ログ」で同じ期間とリソース ID に絞り、`Event` の件数を照合します。
3. 「構成」で OS、IP、電源・接続状態を確認します。ハートビートが報告するプライベート IP と Azure NIC の IP は取得元が異なります。

パネルを調整する場合は、編集モードでクエリ項目の「編集」を開きます。ログ検索先は `Workspace`、監視対象は `Machines`、検索期間は `TimeRange` に連動しています。
